Selectors: pointing CSS at the right elements

Selectors pick which elements a rule styles. Here are the basics, attribute selectors, and the combinators that target elements by their position in the markup.

1. Element, class, and ID selectors

The element selector colors every <p>.

The class selector "highlight" colors everything sharing that class.

The ID selector "unique" colors only this one element.

Note the source order in the CSS: even though the class and ID rules come later, an ID beats a class beats an element — specificity, not order. See specificity.html for the details.

2. Attribute selectors

[href^="https"] targets links starting with https

Attribute selectors add no extra weight beyond a class — they score the same as a class in the specificity tally (see the note's §4.2).

3. Combinators

Descendant: `.wrap p`

I'm a direct <p> inside .wrap.

I'm a <p> nested one level deeper — still matched.

Child: `.wrap > p`

I'm a direct <p> child of .wrap — matched.

I'm nested inside .inner, not a direct child — NOT matched.

Adjacent sibling: `h3 + p`

Heading

I come right after the <h3> — matched.

I come after a <p>, not the <h3> — not matched.

General sibling: `h3 ~ p`

Heading

I follow the <h3> — matched.

I follow it too — matched (all following siblings match).

Space = any descendant, > = direct child, + = the next adjacent sibling, ~ = all following siblings. And in specificity terms, none of the combinators add any weight — .wrap > p scores the same as .wrap p.

4. Combining selectors

.actions button is a descendant combinator; [disabled] is an attribute selector. Together they let CSS style state without extra classes.
